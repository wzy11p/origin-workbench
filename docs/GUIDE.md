# 从一个想法开始

## 1. 先留下原话

在首页写下你想做什么，点击“记下想法”。不用先想好产品名，也不用一次写清所有背景。尚未提交的文字会在本机暂存。

创建项目后，把相关想法放进项目。原话仍然保留，后面的蓝图是进一步整理。

## 2. 把问题逐步说清楚

进入项目总览的“产品蓝图”，先回答当前最关键的一问：谁遇到了什么问题，在什么情况下发生，怎样才算变好。暂时不知道的可以稍后补充。

如果已经使用 PRD 方法填写过答案，蓝图会带入相应内容。自己手动保存的写法优先。可以在需要时导入资料、选择原文引用、用决策卡比较方案。

## 3. 收窄到一个可以制作的版本

在“需求与验收”写具体需求。将第一版和稍后分开；每项需求同时说明成功结果以及失败时怎样恢复。

例如“保存想法”可以写成：正常时保存原话并能再次打开；网络或磁盘错误时保留输入并允许重试。比“支持保存”更容易交给别人实现和验收。

## 4. 形成可以交接的文件

“检查与交付”会列出缺口。它检查结构是否完整，不能替你证明市场需求存在。补完关键缺口后整理新 PRD，原有文档继续保留，可以比较两稿。

需要交给他人时，导出交付 ZIP；只会带出这份文档采用的相关来源与附件。需要以后恢复整个项目时，使用项目包；两者用途不同。

## 5. 做完后记录真实结果

在“验证与回看”写下准备验证什么、通过条件、实际发生了什么，再决定继续、调整、暂缓或停止。尚未完成实际测试时保留“待验证”。

## 可按需要使用的工具

- **资料**：导入报告、访谈、截图或表格，查看解析状态与原文。错误或部分解析时仍保留原件。
- **方法**：按步骤思考和保存，不需要一次完成整套流程。
- **决策**：列出选项、选择、依据和反证，再自己确认。
- **偏好**：记录长期希望遵循的写法、取舍和风格。项目偏好可以覆盖全局偏好。
- **画布**：把流程与结构画清楚，可编辑并保留历史。
- **模型评审**：在“模型与设置”填写自己的服务信息；仅在需要模型意见时使用。调用会把选定上下文发送给该服务。

## 保存与恢复

遇到保存失败，先保留当前草稿；不要把错误提示理解成内容已写入。若发现版本冲突，重新载入后核对再保存。

应用打开时会定期备份项目，备份保留最近七天；恢复会生成新项目。重要项目也建议手动导出并放在另一处。项目包不包含模型密钥，并不等于所有应用设置的完整备份。
