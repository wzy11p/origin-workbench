## 本轮发现并修复的问题

- 整理源码目录后，画布依赖仍依靠旧机器上的链接：改为安装时建立当前仓库内部的相对链接，并保护已有不兼容目录。
- 品牌改名后，帮助和反馈仍指向其他项目：统一为原点入口；反馈不再自动采集或上传资料、日志和截图。
- 缓存的原项目更新仍可能重新出现在界面：从界面挂载边界禁用更新恢复与迁移入口。
- 图表刚出现时的缩放点击会被稍后的重置覆盖：让重置在可交互之前完成，补充首帧点击反例。
- 旧原生数据库驱动不能针对当前 Electron 编译：运行迁移改用内置 `node:sqlite`，保留同步事务、回滚与关闭行为。
- 独立项目启动仍可能重指其他应用的数据别名：原点按数据目录隔离自己的别名与临时文件，不改写旧应用路径。
- 发布后的干净环境检查发现，忽略规则误排除了源码内部的 `runtime/` 和 `data/` 目录：将私人运行环境与资料的规则限定到仓库根目录，补齐运行状态源码、对应测试与画布数据模块，再对只有仓库文件的目录执行类型与构建检查。

## 验证边界

- 当前验证的是这台 Mac 上的独立源码目录、重新安装的依赖与本地构建，不是另一台干净电脑上的安装验收。
- Electron 安装归档使用下载镜像传输，并与 GitHub 官方发布摘要核对；没有把镜像自身声明当作校验依据。
- 未发布签名／公证安装包，也未验证 Windows／Linux 的桌面安装。
- 未重新操作桌面窗口；旧反馈表单的端到端脚本仍需要随新反馈路径更新，本轮不声称桌面 E2E 全通过。
- 未调用外部模型评估真实输出质量、价格或兼容性。
- 未验证大型资料库、长时间运行、复杂画布和扫描文档批处理的峰值资源消耗。
- 测试或缺口检查通过，不能证明产品需求真实或方案一定可行。
