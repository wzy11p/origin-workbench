<h1 align="center">原点工作台</h1>
<p align="center">把一个想法，做成有依据、能交接、可验证的产品方案。</p>
<p align="center">王子瑜 ZiYu · 本地优先 · 中文产品创作工作台</p>

原点工作台是我为个人产品创作设计的桌面应用。写下一句话，放入相关资料，逐步回答关键问题，再把需求、取舍和验收条件整理成 PRD。重要判断由自己确认，材料、修改和决定都可以回看。

它适合做自己的产品、梳理新功能，或把模糊需求交给设计师、开发者与编程工具继续实现。没有模型密钥，也能完成基本创作流程。

**当前版本：0.1.0 源码预览版。** 目前验证环境为 macOS Apple Silicon；尚未提供签名安装包。测试结果与未验证部分见 [验证记录](docs/VALIDATION.md)。

## 它能帮你做什么

| 你正在做的事 | 原点提供的工具 | 留下的结果 |
|---|---|---|
| 有个想法，还没想清楚 | 想法收件箱、草稿恢复、项目归类 | 保留原话的起点 |
| 想知道问题到底是什么 | 一次一问的产品蓝图、可复用的方法答案 | 使用者、问题、场景、成功条件 |
| 手头有报告、访谈或截图 | 本地资料解析、原文引用、来源版本 | 能追溯到原件的依据 |
| 面对几个方案难以取舍 | 决策卡、备选项、理由与反证 | 由自己确认的决定 |
| 需要画清楚思路 | 可编辑画布、流程图、脑图、历史版本 | 可继续修改的方案图 |
| 准备开始制作 | 稳定需求编号、正常与对抗验收、缺口检查 | 范围明确的首版需求 |
| 要把方案交给别人 | 新 PRD 草稿、来源快照、交付 ZIP | 不依赖本应用也能阅读的交付包 |
| 做完后判断有没有用 | 验证计划、实际结果、继续／调整／停止 | 可回看的学习记录 |

另有个人偏好档案、多模型评审、项目导入导出和滚动备份。模型意见先保留为草稿；再次整理 PRD 创建新版本，不覆盖手写内容。

## 一条清楚的使用路径

```text
记下想法 → 产品蓝图 → 需求与验收 → 检查与交付 → 验证与回看
              ↑          ↑             ↑              │
              └──── 资料、方法、决定、画布、偏好 ────────┘
```

例如，你想做一个“给自由职业者整理客户需求”的工具：先写下这个想法，导入一次访谈，把首版收窄到需求记录与确认，列明保存失败怎样恢复，再整理 PRD。后续访谈推翻了原来的判断，相关文档会提醒你复核。

## 我的产品取舍

- **先记下，再整理。** 入口不要求填完一张长表，原始表达和草稿先留下。
- **少重复劳动。** 已填写的方法答案可以进入蓝图和 PRD，不必来回复制。
- **让判断有依据。** 事实、假设、模型建议和自己的决定分开记录。
- **允许改变主意。** 来源、偏好和决定保留历史，变化会提醒相关产物待复核。
- **交付可以带走。** PRD 与相关资料可导出为普通文件，项目包可恢复为新项目。
- **界面保持安静。** 简洁中文界面，主流程突出当前一步，其余工具按需使用。

## 从源码运行

准备 Git、Node.js 22／24、Bun 1.3.9、Python 3.12 和 uv。完整说明见 [安装与运行](docs/SETUP.md)。

```sh
git clone https://github.com/wzy11p/origin-workbench.git
cd origin-workbench
./scripts/setup.sh
./scripts/build.sh
./启动原点工作台.command
```

首次安装需要网络下载依赖；日常资料解析在本机执行。模型评审会把你选择的上下文发送到自己配置的模型服务。项目资料和备份默认位于本机 `data/`，不进入 Git。

源码仓库不携带 Node 依赖、Python 环境、大模型权重、后端二进制或个人数据。下载源码的大小与安装后磁盘占用、运行内存是三个不同指标。
